## 一、目标与先决核对

把此前《艾瑟兰德》第七周期与整合存档的冲突真正查清并尽可能解决，同时核验本仓库 GitHub Pages 的内容一致性、导航与手机阅读体验。不要只输出错误清单便停止，也不要为了完成任务而制造未经证实的正史。

开始前读取本仓库默认分支最新的 `README.md`、`TRPG_RULES.md`、`aetherland/RULES.md`、`aetherland/HANDOFF.md`、`aetherland/canonical-save.md`、相关 `history/cycles/` 原始周期记录、`aetherland/reference/` 规则及财务审计、现有 `aetherland/audits/` 审计记录、`SITE_GUIDE.md`、站点 `index.html` 与实际部署页 `https://msipla.github.io/Archives/`。必要时查 `Msipla/Conversation-Archives` 的 `AGENTS.md` 与 `management/REPOSITORY-GOVERNANCE.md` 了解跨仓库职责，不把它的历史摘要当作正史。先检查最新提交、分支及是否有其他窗口并发写入，不能依赖旧聊天的进度描述。

## 二、档案冲突核验与处理权限

以**玩家最新明确裁定和实际发生的剧情**为首要证据，结合事件发生顺序、周期原始存档和最新权威整合存档核对。重点检查第七周期及其后续状态的时间线、暂停点、下一条 GM 编号、角色 HP/MP/XP、技能动作经济、装备、消耗品、战利品、个人与家族账目、NPC 关系、任务和未决规则。不要仅凭“文件更新时间较晚”推翻已发生的剧情。

本任务明确授权以下自主修复，不必每个确定性错误都向玩家请示：

1. 可证实的错字、断链、重复状态、过时导航、错误的历史/当前标签：直接做最小修复。
2. 原始记录或玩家明确裁定足以唯一确定事实的冲突：修正相应当前权威状态和必要的引用；保留原始周期档案、来源证据与 Git 历史。
3. 根据多份可靠记录和明确事件顺序能够合理重建的缺口：可作最小一致性修复，但需在现有合适审计位置注明依据、推导链及不确定性；不得伪装成原始剧情逐字记录。
4. 对于原始剧情本身相互矛盾、证据不足、存在多个同样合理版本，或涉及玩家尚未裁定的重大选择/规则：保留 CONFLICT/OPEN，不擅自决定或编造数值、行动、事件和人物关系；仅暂停该争议部分，继续处理其余可确定事项，最后集中请玩家裁定。

本任务的自动修复授权**仅限有证据的档案一致性问题**，不授权推进跑团剧情、代玩家掷骰、替玩家选择、修改已发生事件、调整游戏难度或重写设定。不要为了修复冲突而删改历史周期原件。确需触及当前权威存档时，先对照最新文件和相关证据，再做最小必要变更，提交后回读验证。

## 三、Pages 核验与最小修复

核验 `https://msipla.github.io/Archives/` 对应的实际部署内容、仓库 Pages 发布配置和源码：

- 首页能否进入《艾瑟兰德》与《渊城》各自的阅读入口；世界资料是否隔离。
- 手机屏幕下导航、目录、文字、滚动、长文阅读与必要的剧透提示是否可用。
- `canonical-save.md`、周期档、世界观资料和新增文档是否可被站点正确发现与阅读；GitHub API/CDN 不可用时的回退行为是否合理。
- 检查实际断链、旧入口、错误的“最新”指向、缓存或发布滞后；区分源码正确、部署成功、浏览器实测通过。
- 不把公开网页的剧透提示当成隐私保护；不得上传需要保密的 GM 信息、密钥或私人资料。

只有发现真实问题时才修复。优先沿用既有静态 HTML/CSS/JS、现有导航和发布机制；**不引入新框架、不重做美术、不无故扩展功能**。如环境不支持实际浏览器测试，明确列出未验证项目，不能把源码审查冒充实测。

## 四、并发、提交与验收

- 修改前核对目标文件最新 SHA、差异与并行工作；不覆盖其他窗口的新剧情或新提交。冲突时保留较新可靠成果并重新评估。
- 优先更新现有适当文件，禁止无必要新建一批报告、索引、备份和管理层级。只在确有必要时将证据简要补入已有审计位置。
- 每次修复说明问题、来源、修改理由及影响；修复后回读文件并检查引用。Pages 改动要区分提交、部署和实际浏览器验收。
- 不修改 `Msipla/-Moonlit-Halt`、`Msipla/Shared-Memories` 或其他世界的正史；跨仓库信息只读核对即可。
- 收尾报告包含：已确认的冲突及修复结果、未决且必须玩家裁定的问题、Pages 实际验证范围与结果、相关提交链接、剩余风险。若核验后无需修改，也应明确说明“未改动”及证据，不制造提交。
